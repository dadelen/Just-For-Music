# Apple Music Lyrics 二次开发需求文档 V2.1

本文档定义二次开发目标和验收要求。具体功能的实现状态以源码、阶段提交和测试报告为准。

## 一、项目目标与适配范围

基于原项目的歌词缓存解析、播放监测和同步引擎，打造具有现代原生 macOS 设计语言的轻量级歌词播放器。采用渐进式改造，复用现有核心能力，并控制改动范围。原项目为 [Takpap/apple-music-lyrics](https://github.com/Takpap/apple-music-lyrics)。

### 1.1 核心目标

1. 顶部状态栏显示实时原文逐字歌词，以及上一首、播放／暂停、下一首三个按钮。
2. 点击歌词区域展开简洁播放器，下方提供设置、退出两个等宽入口。
3. 桌面悬浮歌词采用左侧动态黑胶、右侧原文及简体中文译文的双栏布局。
4. macOS 26+ 使用原生 Liquid Glass，较旧系统使用传统毛玻璃，统一高圆角设计。
5. 使用 Apple 本地翻译能力处理符合条件的外语歌词。
6. 前奏、间奏和有可靠时间边界的尾奏显示 KTV 式三个点进度动画。
7. 删除指定的导出、锁定、穿透、全局快捷键和旧双布局功能。

### 1.2 平台与架构

- 仅适配 Apple Silicon Mac，构建架构为 `arm64`。
- 最低运行系统为 macOS 13。
- 删除 Intel／`x86_64` 构建分支、Universal 双架构打包及对应兼容处理。
- 主程序、播放辅助进程、安装包、更新包及 CI 验证均面向 `arm64`。
- 使用支持所需正式 API 的 SDK 构建，并为新系统 API 添加可用性检查。

| 运行系统 | 窗口材质 | 自动翻译能力 |
| --- | --- | --- |
| macOS 13–14 | `NSVisualEffectView` | 显示已有缓存译文 |
| macOS 15 至 26 之前的版本 | `NSVisualEffectView` | Apple 本地翻译 |
| macOS 26.0–26.3 | `NSGlassEffectView` | Apple 本地翻译 |
| macOS 26.4+ | `NSGlassEffectView` | 可显式选择高质量策略，并按实际可用性降级 |

### 1.3 本次修订确认

- 仅支持 Apple Silicon。
- 同一句或同一歌词行夹杂中文和外语时，整行跳过自动翻译，保留原文。同一首歌中独立的纯外语行仍可按规则翻译。
- 状态栏采用三级显示策略，与第 2.2 节表格一致。
- 远程仓库由用户自行创建。Agent 获得用户提供的仓库地址及明确操作指示后，再配置远程地址、推送或发布。

## 二、顶部系统状态栏

### 2.1 布局与交互

从左到右排列为“实时原文歌词、上一首、播放／暂停、下一首”。优先使用一个 `NSStatusItem`，歌词区域和控制按钮具有独立的布局与点击响应。

- 保留原项目逐字高亮，以及高亮和未高亮颜色自定义。
- 长歌词在歌词视口内平滑水平滚动，三个控制按钮固定在右侧。
- 使用 SF Symbols，播放／暂停图标跟随真实播放状态。
- 点击控制按钮直接操作 Apple Music，点击歌词区域打开应用菜单。
- 提供悬停反馈、合理点击区域和辅助功能标签。
- 状态栏只显示原文歌词。
- 无歌词、加载中、播放停止或发生错误时，使用对应的简洁状态显示。

### 2.2 三级空间自适应

| 等级 | 显示内容 |
| --- | --- |
| 1 | 完整歌词视口与三个控制按钮 |
| 2 | 缩窄歌词视口与三个控制按钮 |
| 3 | 音乐图标，作为菜单入口 |

- 第二级继续支持歌词平滑水平滚动。
- 压缩歌词可视区域时保留完整歌词文本，去除现有状态栏渲染中的固定字符截断。
- 当前演唱文字尽可能保持可见，高亮和滚动共用同一播放时间依据。
- 暂停时固定高亮与滚动位置，恢复后继续。
- 切歌和拖动进度后重新定位。应用内定位成功后立即校正，Music.app 内的外部操作在收到有效播放采样后校正。
- 短歌词居中显示，控制按钮的位置不随文本长度变化。
- 尽可能复用原项目的水平滚动算法。
- 自动模式结合屏幕尺寸、刘海区域和公开 API 可获得的信息选择保守宽度。
- 提供手动紧凑／图标模式。系统空间极小时允许状态项被系统隐藏。
- 验收不以精确获取其他应用占用后的实时剩余宽度为前提。

### 2.3 KTV 式三个点空档进度

第一条歌词开始前，以及两句歌词之间的明显空白区间，显示三个点 `…`。可靠歌曲时长和歌词结束时间可确定尾奏边界时，尾奏也可使用相同显示。

三个点根据实际播放时间由左至右逐渐高亮，进度按下式计算。

```text
p = clamp((t - t_start) / (t_end - t_start), 0, 1)
```

- 空档必须具有有效起止时间，且 `t_end > t_start`。
- 优先使用 TTML 显式结束时间、可靠的词级结束时间、下一句开始时间和有效歌曲时长。
- 对现有歌词模型作最小扩展，保留结束时间及其可靠性，避免把渲染补值当作真实空档边界。
- 极短间隔继续沿用歌词显示，避免闪烁。最小空档阈值在开发时通过实际样本确认。
- 歌词重叠时依据仍在演唱的内容处理，避免误报空档。
- 暂停时冻结，恢复后继续，定位播放后重新计算。
- 下一句开始时切回正常歌词。
- 时间边界不足时保留正常状态显示。
- 三个点表示确定区间中的播放进度，采用时间驱动的渐进高亮。
- 状态栏与浮窗复用同一空档判断逻辑，避免显示不一致。

## 三、点击状态栏后展开的菜单

### 3.1 简洁播放器

菜单顶部保留播放器卡片，参考用户指定的 Apple Music Lyrics 播放器截图。

- 左侧显示当前歌曲的真实专辑封面。
- 右侧显示歌曲标题、歌手／作者及专辑信息。
- 右侧中下方居中排列上一首、播放／暂停、下一首。
- 底部提供播放进度条、已播放时间和剩余时间。
- 歌名使用较大字号和较高字重，作者与专辑使用较小字号和次要颜色。
- 歌名和作者信息在封面右侧的内容区域内水平居中。
- 长标题合理换行或截断，为播放按钮保留固定空间。
- 整体采用简洁、高圆角、系统材质设计。
- 播放器与浮窗黑胶共享封面加载结果。封面缺失或加载失败时显示占位图。
- 封面获取由歌曲变化触发，避免在播放位置采样中重复请求。

### 3.2 一级功能入口

播放器下方只保留两个水平等宽按钮。

| 左侧 50% | 右侧 50% |
| --- | --- |
| 设置 | 退出 |

- 两个按钮使用系统图标和高圆角。
- 设置打开独立设置窗口，退出关闭应用。
- 一级菜单的内容限定为播放器卡片和这两个入口。
- 诊断日志、更新检查及其他保留配置迁入设置窗口。
- 黑胶组件仅用于桌面悬浮窗口。

### 3.3 独立设置窗口

| 分组 | 内容 |
| --- | --- |
| 常规 | 悬浮歌词显隐、状态栏显示模式、其他保留的通用选项 |
| 歌词 | 高亮颜色、未高亮颜色、字体与显示、平滑滚动、KTV 空档动画、手动刷新歌词 |
| 翻译 | 自动翻译开关、目标语言、质量策略、本地语言资源状态与系统下载入口 |
| 悬浮窗口 | Small／Large、背景透明度与材质外观、显隐、跨桌面与全屏显示、缓存译文与音译显示 |
| 更新与诊断 | GitHub 更新检查、下载更新、日志查看、复制与定位 |

设置窗口展示配置和状态信息。所有设置保存在本地，重新启动后恢复。

## 四、UI 视觉设计

### 4.1 Liquid Glass 与辅助功能

- macOS 26+ 使用 `NSGlassEffectView`，较旧系统使用 `NSVisualEffectView`。
- 根据系统版本选用单一背景材质，内容通过相应容器正确承载。
- 跟随浅色和深色外观。
- 响应系统降低透明度和提高对比度设置，降低透明度时提供不透明背景。
- 透明度设置作用于背景外观，保持文字和控件可读。
- 设置名称准确表达应用实际控制的外观属性。
- 不添加自定义背景色或玻璃着色，文字对比度由系统外观与辅助功能设置协调。
- 系统启用减少动态效果时，降低装饰性运动和转场，保留歌词进度信息。

### 4.2 视觉规范

- 主面板圆角建议约 24 pt，小控件约 12–16 pt。
- 播放按钮、进度条可采用胶囊形。
- 阴影、描边和装饰动画保持克制。
- 窗口底面完全采用系统玻璃材质，随背景和深浅色外观呈现效果。

### 4.3 黑胶视觉参考

桌面浮窗以用户指定的第一张深蓝色黑胶图片为视觉参考，提取黑色外圈、细微同心圆纹理、圆形真实封面和白色简化唱针。窗口底面按用户最新要求使用原生玻璃，不铺设蓝色或其他自定义底色。

专辑封面随实际歌曲变化，保留封面本身的颜色。参考图片用于指导组件绘制和布局。

用户已提供黑胶参考图。播放器参考截图待提供，先按本规格的布局要求实现。

## 五、桌面悬浮歌词窗口

### 5.1 双栏布局

同一个高圆角玻璃窗口内，左侧放动态黑胶及简化唱针，歌名和歌手在唱片下方分两行居中。右侧放原文歌词和简体中文译文。

### 5.2 Small 与 Large 固定尺寸

- 只允许 Small、Large 两档固定尺寸，通过设置窗口选择。
- 两档使用相同的左右双栏布局。
- 移除自由拖拽边缘缩放能力。
- 具体尺寸结合歌词长度、屏幕空间和组件比例确定，两个尺寸都应完整容纳唱片、唱针、原文和译文。
- 唱片保持圆形，歌词区域独立换行和滚动。
- 窗口可自由拖动，按显示器记忆位置。
- 从旧版迁移时保留可用的位置记录，将窗口大小映射到新预设。
- 切换尺寸时维持合理锚点，并将窗口约束在可用屏幕区域内。
- 保留置顶、跨桌面及全屏应用显示能力，按系统公开窗口行为进行验收。

### 5.3 动态黑胶组件

新增独立组件，例如 `VinylPlayerView.swift`，包含黑胶底盘、同心圆纹理、中央圆形封面和简化白色唱针臂。

| 播放状态 | 黑胶行为 | 唱针行为 |
| --- | --- | --- |
| 正在播放 | 持续匀速旋转 | 靠近唱片 |
| 暂停 | 停在当前角度 | 平滑挪开 |
| 恢复播放 | 从暂停角度继续 | 平滑回位 |
| 切换歌曲 | 更新封面并平滑过渡 | 根据实际播放状态过渡 |
| 停止播放 | 停止转动 | 挪开 |

- 默认每 6 秒旋转一圈。唱片使用柔和投影和固定方向的反光，保留真实封面的颜色。
- 使用 Core Animation／`CALayer` 旋转，黑胶和封面置于同一个旋转容器。
- 唱针单独渲染。
- 通过 Core Animation 的暂停和恢复时间控制维持角度连续。
- 黑胶动画由现有播放状态驱动，旋转由 Core Animation 执行。
- 悬浮窗口隐藏时暂停不必要的可视动画，重新显示时按当前状态恢复。
- 歌词时间同步与黑胶动画各自完成绘制，共享现有播放状态来源。

### 5.4 原文与译文层级

- 原文为主视觉，字号更大、字重较高、颜色较亮。
- 原文左对齐。当前行使用较大粗体并保持逐字高亮，邻行降低透明度并轻微模糊。
- 手动滚动停止 4 秒后，浮窗平滑回到当前播放行。
- 译文字号约为原文的 75%–85%，使用较轻字重和可读的次要颜色。
- 译文位于对应原文下方，按行同步切换。
- 长译文在歌词区域内换行与滚动，保持唱片区域尺寸稳定。
- 翻译异步补齐后保持当前播放行及手动浏览位置，减少布局跳动。
- Small 和 Large 使用相同视觉层级。

### 5.5 保留交互

- 手动滚动浏览歌词、停止滚动后按行吸附，以及自动恢复播放跟随。
- 点击歌词跳转播放位置。
- Apple Music 缓存附带的翻译和音译，按设置显示。
- KTV 式空档进度。
- 窗口拖动、置顶、多显示器位置记忆、跨桌面和全屏显示。

## 六、Apple 本地自动翻译

### 6.1 语言规则

目标语言默认为简体中文。判断依据是歌词内容，结合整首歌和逐行文本的语言识别结果。

| 歌词情况 | 自动翻译规则 |
| --- | --- |
| 简体中文行 | 保留原文 |
| 繁体中文行 | 保留原文 |
| 英语、日语、韩语、法语、西班牙语等纯外语行 | 系统支持对应语言组合且置信度足够时翻译 |
| 同一句／同一行夹杂中文和外语 | 整行跳过自动翻译，保留原文 |
| 同一首歌交替出现中文行和纯外语行 | 中文行保留原文，纯外语行分别判断 |
| 无法可靠识别、无实质文本或不支持的语言组合 | 保留原文 |

混合歌词行的规则适用于自动翻译请求。Apple Music 缓存已附带的译文和音译仍按既定显示设置处理。

### 6.2 语言识别

1. 获取完整歌词文本，过滤纯空白、无意义符号和时间戳。
2. 使用 `NLLanguageRecognizer` 识别整首歌的主语言，取得候选语言及置信度。
3. 对需要判断的歌词行补充识别，结合整首歌上下文减少短句误判。
4. 可靠识别为中文的行跳过自动翻译，整首均为中文时直接结束判断。
5. 识别为中外文混合的行整行跳过，不拆分外语片段翻译。
6. 纯外语行检查系统语言组合支持情况，并按源语言分组。
7. 对短句、语气词、人名及语言判断不确定的行采取保守跳过策略。
8. 切歌或歌词内容更新后重新判断。

日语包含汉字，必须结合语言识别与上下文判断，汉字比例只能作为辅助信息。

### 6.3 翻译引擎与系统分支

- 使用 Apple `Translation` Framework 执行本地翻译。
- macOS 13–14 仅显示缓存已有译文。
- macOS 15+ 启用本地自动翻译，使用正式 SDK API 与可用性检查。
- macOS 15 的会话接入可通过 AppKit 中嵌入 SwiftUI 翻译宿主完成，正确管理宿主生命周期。
- macOS 26+ 可通过已安装语言包的会话接口执行翻译。
- 语言包缺失时通过系统支持的翻译界面提示并请求下载，由用户确认。
- macOS 26.4+ 可显式使用 `highFidelity` 策略，按系统模型实际可用性回退到传统本地策略。
- 语言支持情况通过运行时 API 检查，设置中反映当前可用能力。
- 首次下载语言资源需要网络，已具备资源的翻译在本地执行。
- 目标语言数据结构保留扩展能力，当前默认配置为简体中文。

Apple 官方说明可参考 [Translation API](https://developer.apple.com/videos/play/wwdc2024/10117/) 和 [翻译策略配置](https://developer.apple.com/documentation/translation/translationsession/configuration/init%28source%3Atarget%3Apreferredstrategy%3A%29)。

### 6.4 译文来源优先级

1. Apple Music 本地缓存已有且能确认语言的中文译文。
2. 符合自动翻译规则的 Apple 本地翻译结果。
3. 译文不可用时显示原文。

在现有数据模型上增加必要的语言与来源信息，可靠区分原文、缓存译文、音译及机器译文。保留现有缓存解析和匹配机制，补充元数据与选择逻辑。

### 6.5 执行、缓存与隔离

- 取得歌词后立即显示原文，异步翻译符合条件且缺少中文译文的行。
- 每个批次只包含同一种源语言，使用行标识将返回结果对应到原行。
- 耗时识别、缓存读写及翻译调度避免阻塞 UI。
- 缓存键包含歌曲身份、源语言、目标语言、歌词内容版本，以及影响结果的翻译策略。
- 使用稳定的歌词内容指纹进行持久化缓存判断。
- 重复歌词复用结果，避免重复请求。
- 保留原始行及词级时间戳。
- 切歌、歌词更新或关闭自动翻译时，取消可取消的任务，并通过请求代次或版本检查隔离过期结果。
- 翻译失败时继续正常播放和显示原文，设置中提供资源或失败状态。
- 开关可随时关闭自动翻译，缓存附带译文按独立显示设置处理。

### 6.6 显示范围

| 界面 | 原文歌词 | 译文 |
| --- | --- | --- |
| 顶部状态栏 | 显示 | 隐藏 |
| 展开播放器菜单 | 隐藏 | 隐藏 |
